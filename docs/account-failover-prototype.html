Orca 1.4.272 today: nothing reacts to included usage. At 100% with paid credits left, Orca’s own reading counts as room (rateLimitShowsRoom true, rateLimitSpentUntil undefined), so the conversation goes on to paid usage. Only a hard usage-limit error stops it.
Proposed: the host checks a fresh reading at each provider-request boundary and continues on a login with included usage, or pauses. Readings and this UI are not a spend cap. A request already in flight can still cost paid usage, so zero paid usage is not guaranteed.
Decisions kept
  • On by default for every eligible login of the same provider, discovered automatically. No prompt, picker, setup or usage dashboard.
  • Eligible means inside the workspace’s authorized sharing scope, not covered by the same organization window, able to run the model, and with confirmed included usage. The Acme Codex login is never used.
  • System default is collapsed onto the login it points to.
  • A rounded 100, a stale or unknown reading, another model’s window and a retry are not proof.
  • When no eligible login has included usage, one line shows the earliest known reset and Check now. It doesn’t cycle.
